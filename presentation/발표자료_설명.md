# Brawl Assistant 발표 자료: 슬라이드별 이미지와 설명

> **이미지 출처**
> - 앱 화면(01~11번)은 실제로 빌드한 앱을 **iPhone 17 Pro 시뮬레이터(iOS 26.2)**에서 자동 UI 테스트로 찍은 것입니다. GitHub Actions에서 2026-11-19에 실행했습니다. 실제 iPhone 사진은 아닙니다.
> - 웹 화면(00a, 00b)은 같은 날 웹 페이지를 실제로 띄워 찍었습니다.
> - 12~14번은 설명용으로 그린 도식입니다.
> - 플레이어 정보와 '지금 열린 맵' 목록은 **데모 데이터**입니다. 서버(공식 API 키)를 아직 배포하지 않았기 때문입니다. 추천 결과는 실제 엔진으로 계산한 값입니다. ▶를 누른 뒤의 새 추천은 테스트 중에 실시간으로 계산했습니다.
>
> **슬라이드 구성:** 각 슬라이드는 '넣을 이미지 / 슬라이드 문구 / 발표자 노트'로 되어 있습니다. 슬라이드 문구는 화면에 그대로 넣을 짧은 글입니다. 발표자 노트는 말로 설명할 내용입니다.

  - 이 계산 로직을 앱에서 새로 만들지 않고 **같은 파일 그대로** 쓰는 것이 원칙이었습니다(슬라이드 9).

## 슬라이드 3. 앱 홈 화면: 플레이어 · 지금 열린 맵

- **넣을 이미지:** `images/01-home-top.png` (전체 화면). 확대용으로 `images/01b-player-and-maps-crop.png`
- **슬라이드 문구**
  - 플레이어 카드: 이름 · 태그 · 보유 브롤러 81/108 · 트로피
  - 지금 열린 맵: 공식 이벤트 맵 타일, 한 번 탭하면 추천
  - 최근 경기 맵 자동 선택 (초록 '최근 경기' 표시)
  - 하단 고정 버튼: Dynamic Island 켜기 / 끄기
- **발표자 노트**
  - 맨 위는 웹과 같은 금색 'DRAFT ROOM' 로고입니다. 그 아래 칩에는 상태(READY/LIVE), 현재 맵 풀 193개, 브롤러 108명이 표시됩니다.
  - **플레이어 카드:** 게임 태그(#2PP 형식)를 한 번 넣으면 Supercell 공식 API에서 내가 가진 브롤러와 파워 레벨을 받아 옵니다. 이후 추천은 내가 가진 브롤러로만 만듭니다. 화면 예시는 108명 중 81명을 보유한 경우입니다.
  - **지금 열린 맵:** 공식 이벤트 로테이션에서 지금 열려 있는 맵만 타일로 보여 줍니다. 수백 개 맵 중에서 고를 필요 없이 몇 개 중에서 한 번만 누르면 됩니다.
  - **최근 경기 맵:** 공식 전적에서 가장 최근 경기가 45분 이내이고 그 맵이 아직 열려 있으면, '최근 경기'로 표시하고 앱을 열 때 자동으로 고릅니다. 같은 이벤트를 연달아 하는 경우가 많다는 점을 이용했습니다.
  - 하단 고정 버튼으로 Dynamic Island 표시를 켜고 끕니다. 꺼져 있을 때는 금색 '켜기' 버튼입니다. 켜져 있으면 스크린샷처럼 빨간 테두리의 '끄기' 버튼으로 바뀝니다.

## 슬라이드 4. 추천 조합 리스트

- **넣을 이미지:** `images/02-home-ranking.png` (위쪽 리스트 부분). 1위 줄은 `images/01-home-top.png` 맨 아래에 있습니다.
- **슬라이드 문구**
  - MAP INTEL: 맵 이름 · 영문명 · 모드 · 인원
  - 종합 점수 순 TOP 6 조합 (1위는 금색 테두리)
  - 각 줄: 순위 · 브롤러 3명(희귀도 색 테두리) · 추정 승률 · 종합 점수
  - 줄을 누르면 그 조합의 상세 카드로 바뀜
- **발표자 노트**
  - 맵 이름 위의 'MAP INTEL · BOUNTY'와 큰 맵 이름은 웹의 디자인을 그대로 가져왔습니다.
  - 추천 조합은 엔진이 매긴 종합 점수 순서입니다. 오른쪽 큰 숫자는 추정 승률, 아래 작은 숫자는 종합 점수입니다. 예: 1위 파이퍼·코스모·볼트는 57.5%, 종합 84점입니다.
  - 추정 승률과 종합 점수는 다른 기준이라, 2위의 승률(60.2%)이 1위보다 높을 수도 있습니다. 종합 점수에는 승률 외에 역할 밸런스와 카운터 내성도 들어가기 때문입니다.
  - 초상화 테두리 색은 브롤러 희귀도 색입니다(웹 카드와 동일).
  - 화면 아래 '3,276개 조합 시뮬레이션'은 이 맵에서 실제로 계산한 조합 수입니다. 추정 승률은 엔진 계산값이며 공식 통계가 아니라고 화면에 함께 적었습니다.

## 슬라이드 5. BEST TEAM 상세 카드

- **넣을 이미지:** `images/02-home-ranking.png` 아래쪽(브롤러 카드), `images/03-home-score-reasons.png` (점수·평가 막대·근거·드래프트 순서), `images/04-home-ban-menu.png` 위쪽(밴 추천)
- **슬라이드 문구**
  - S-TIER · BEST TEAM · 조합 유형(밸런스 표준)
  - 브롤러 카드: 픽 순서(1픽~3픽) · 역할 · 실전 승률 효과(%p)
  - 큰 점수 84/100 + 추정 승률 · 시뮬레이션 수 · 카운터 내성
  - 평가 막대 11개: 높으면 금색, 낮으면 빨강
  - 왜 이 조합인가 · 드래프트 순서 · 밴 추천(천적)
- **발표자 노트**
  - **브롤러 카드:** 브롤러마다 희귀도 색으로 빛나는 카드에 정보를 담았습니다.
    - 픽 순서: 1픽 파이퍼는 카운터가 적어 먼저 골라도 안전하고, 3픽 볼트는 카운터당하기 쉬워 마지막에 고릅니다.
    - 역할: 저격 앵커, 견제·마무리, 전방 압박.
    - 실전 효과: 최근 4주 실전 데이터에서 이 맵의 승률을 얼마나 올렸는지입니다. 예: 볼트 +11.1%p.
  - **점수와 지표:** 84점은 100점 만점의 종합 점수입니다. 옆에는 추정 승률 57.5%, 시뮬레이션 조합 수 3,276, 카운터 내성 98이 있습니다.
  - **평가 막대:** 실전 승률 데이터, 맵 적합도, 사거리 커버리지, 역할 밸런스, 군중 제어, 지속력, 벽 대응, 부쉬 장악, 카운터 내성, 시너지, 메타 파워의 11개 항목입니다. 0.72 이상이면 금색, 0.4 미만이면 빨강입니다.
  - **근거 문장:** 엔진이 만든 그대로 보여 줍니다. 예: "시야선이 길게 열린 맵(55%)이라 장거리 견제 브롤러의 가치가 높습니다."
  - **밴 추천:** 이 조합을 가장 강하게 카운터하는 상위 메타 브롤러입니다(클랜시, R-T, 미나).

## 슬라이드 6. 설정 화면

- **넣을 이미지:** `images/05-home-settings.png` (설정·데이터 출처). 메뉴는 `images/04-home-ban-menu.png`
- **슬라이드 문구**
  - 보유 브롤러만 추천 (켜기/끄기, 최소 파워 1~11)
  - 추천이 바뀌면 Dynamic Island 펼치기 (기본 꺼짐)
  - 화면 인식은 선택 기능으로만 남김
  - 데이터 출처 표시 · 비공식 팬메이드 도구 고지
- **발표자 노트**
  - '보유 브롤러만 추천'을 끄면 전체 브롤러 기준으로 추천합니다. 플레이어 연결 화면에서는 최소 파워도 정할 수 있습니다. 예를 들어 파워 9 이상만 쓰고 싶으면 그 브롤러들만 후보가 됩니다.
  - '추천이 바뀌면 Dynamic Island 펼치기'는 게임 중 방해가 될 수 있어 기본으로 꺼 두었습니다.
  - 예전 방식인 화면 인식(화면 방송 + 글자 인식)은 '화면 인식으로 맵 찾기 (선택)' 메뉴로만 남겼습니다.
  - 맨 아래에는 데이터 출처(Supercell 공식 API, Brawlify, BrawlTime)와 Supercell과 관련 없는 비공식 도구라는 문구를 넣었습니다. Supercell 팬 콘텐츠 정책 때문입니다.

## 슬라이드 7. Dynamic Island: 축소형과 펼침

- **넣을 이미지:** `images/06b-island-compact-crop.png` (축소형), `images/07b-island-expanded-crop.png` (펼침). 전체 화면이 필요하면 `06-island-compact.png`, `07-island-expanded.png`
- **슬라이드 문구**
  - 축소형: 1위 조합 초상화 3개 + 1위 추정 승률
  - 펼침(길게 누르기): 맵 이름 · 모드 · 상위 3개 조합 · ◀ ▶ 버튼
  - 1위 줄 금색 테두리, 희귀도 색 초상화
- **발표자 노트**
  - 게임을 하는 동안 화면 위쪽 Dynamic Island에 1위 조합 얼굴 3개와 추정 승률(57.5%)이 작게 떠 있습니다.
  - 섬을 길게 누르면 펼쳐집니다. 펼친 화면에는 맵 이름, 모드, 상위 3개 조합과 각 추정 승률이 나옵니다.
  - 오른쪽 위의 ◀ ▶ 버튼이 이번 업데이트의 핵심입니다(슬라이드 8).
  - 디자인은 Apple의 Live Activity 크기 제한(펼침 높이 최대 160pt)을 지키면서 웹 DRAFT ROOM의 글꼴과 색을 그대로 썼습니다. 글꼴은 Lilita One, Black Han Sans, JetBrains Mono입니다.

## 슬라이드 8. 게임 중 ▶ 한 번으로 맵 바꾸기 (핵심)

- **넣을 이미지:** `images/11-before-after-next-map.png` (전후 비교, 16:9 완성본). 개별 이미지: `07b`, `08b`, `09b`, `10b`
- **슬라이드 문구**
  - BEFORE 기습적 움직임 · 바운티 → ▶ → AFTER 폭주 급류 · 젬 그랩
  - 앱을 열지 않고 버튼만 눌러도 추천 계산과 표시가 끝남
  - Dynamic Island와 잠금 화면이 동시에 바뀜
- **발표자 노트**
  - 이 슬라이드가 이번 개발의 결과입니다. 왼쪽은 바운티 맵 '기습적 움직임'의 추천입니다(파이퍼·코스모·볼트, 57.5%).
  - ▶를 누르면 다음으로 열린 맵인 젬 그랩 '폭주 급류'로 바뀝니다. 새 1위는 스파이크·주주·데미안이고 추정 승률은 58.6%입니다.
  - 이 값은 미리 만들어 둔 그림이 아닙니다. 테스트 중에 버튼을 누른 순간 앱이 실제 엔진으로 계산한 결과입니다.
  - 아래 잠금 화면도 같은 내용으로 함께 바뀌었습니다.
  - 동작 순서:
    1. 버튼은 iOS의 `LiveActivityIntent`입니다.
    2. 누르면 iOS가 백그라운드에 있는 우리 앱을 잠깐 깨웁니다. 게임 화면은 그대로입니다.
    3. 앱이 다음 맵의 추천을 가져옵니다. 미리 계산된 게 있으면 그것을 쓰고, 없으면 그 자리에서 계산합니다.
    4. 앱이 Live Activity를 직접 갱신합니다.
  - 이 과정에는 서버도 푸시 알림도 필요 없습니다.
  - ◀ ▶가 도는 순서는 '지금 열린 맵' 목록입니다. 목록이 없으면 랭크 모드 맵 순서입니다.

## 슬라이드 9. 사용 흐름 4단계

- **넣을 이미지:** `images/12-usage-flow.png` (16:9 완성본)
- **슬라이드 문구**
  1. 플레이어 연결 (처음 한 번)
  2. 지금 열린 맵 탭
  3. Dynamic Island 켜기
  4. 게임 중 ◀ ▶
- **발표자 노트**
  - 처음 한 번만 태그를 연결하면, 그 뒤에는 앱을 열어 맵을 누르고 Dynamic Island를 켜는 것으로 준비가 끝납니다.
  - 게임 로비에서 다른 모드로 옮기면 섬을 길게 눌러 ◀ ▶로 맵을 바꾸면 됩니다.
  - 예전 방식과 비교하면 이렇습니다.
    - 예전: 매번 '화면 방송'을 시작하고 끝내야 했고, 게임 화면 글자를 계속 읽느라 배터리를 썼습니다.
    - 지금: 녹화가 없습니다.

## 슬라이드 10. 왜 게임에서 직접 못 읽나 (설계 판단)

- **넣을 이미지:** `images/14-why-not-direct.png` (16:9 완성본)
- **슬라이드 문구**
  - ✕ iOS 앱 격리: 다른 앱의 데이터·화면을 읽을 수 없음
  - ✕ 공식 API: 진행 중 경기 정보 없음, 전적은 경기 후 늦게 반영
  - ✕ 통신 가로채기: 약관 위반, 계정 정지 위험
  - ✓ 공식 데이터로 범위를 좁히고, 마지막 선택은 버튼 한 번
- **발표자 노트**
  - "브롤스타즈 앱에서 바로 정보를 받아오면 되지 않나?"라는 질문에 대한 답입니다.
  - iOS는 보안상 다른 앱의 데이터를 읽지 못하게 막습니다. 브롤스타즈도 다른 앱에 정보를 넘겨주는 기능이 없습니다.
  - Supercell 공식 API에는 '지금 들어갈 맵'이나 '드래프트 픽' 같은 실시간 정보가 없습니다. 전적은 경기가 끝난 뒤에 올라오고, 늦으면 30분 정도 걸린다고 알려져 있습니다(공식이 아닌 라이브러리 문서 기준).
  - 게임 통신을 가로채는 방법은 약관 위반이라 처음부터 제외했습니다.
  - 그래서 공식 데이터로 확실히 알 수 있는 것은 자동으로 하고, 남은 마지막 한 단계만 사용자가 버튼으로 고르게 설계했습니다.
    - 확실히 알 수 있는 것: 보유 브롤러, 지금 열린 맵, 최근 경기 맵.
    - 사용자가 고르는 것: 이번 판의 맵 하나.

## 슬라이드 11. 시스템 구조

- **넣을 이미지:** `images/13-system-architecture.png` (16:9 완성본)
- **슬라이드 문구**
  - 외부 데이터: Supercell 공식 API, Brawlify, BrawlTime
  - 중계 서버: 공식 API 키 보관, 최소 정보만 전달
  - iPhone 앱: 웹과 같은 엔진 파일로 기기 안에서 계산
  - Dynamic Island: 버튼으로 앱이 직접 갱신
- **발표자 노트**
  - **엔진은 하나입니다.** 웹 사이트, iOS 앱, Android 앱이 `engine/draft-engine.js` 한 파일을 같이 씁니다.
    - iOS는 Apple의 JavaScriptCore로 이 파일을 그대로 실행합니다.
    - 웹과 결과가 같은지 87개 시나리오, 517개 조합으로 자동 검사합니다.
  - **서버는 중계만 합니다.** 공식 API 키는 서버 IP에 묶여 있고 비밀 값이라 앱에 넣을 수 없습니다. 그래서 작은 Node 서버가 키를 들고 대신 부릅니다.
    - 앱이 서버로 보내는 것은 플레이어 태그 하나뿐입니다.
    - 서버가 돌려주는 것은 보유 브롤러(id·파워), 최근 경기(모드·맵), 지금 열린 맵입니다.
    - 다른 플레이어 정보는 버리고, 로그에는 태그를 남기지 않습니다.
  - **계산은 전부 기기 안에서 합니다.** 맵 이미지 분석과 조합 계산은 아이폰에서 합니다. 화면 이미지는 어디에도 보내지 않습니다.
  - Live Activity 푸시(APNs)는 선택 기능인 화면 인식을 쓸 때만 필요합니다.

## 슬라이드 13. 한계와 다음 단계

- **슬라이드 문구**
  - 아직 실제 iPhone에서 게임 중 ◀ ▶를 확인하지 않음 (시뮬레이터 검증)
  - 서버 배포 필요: Supercell 개발자 키(서버 IP 등록) → 앱에 서버 주소 설정
  - 실시간 '지금 들어갈 맵'은 공식적으로 알 수 없음 → 사용자가 한 번 선택
  - Android는 아직 화면 인식 방식 → 같은 방식으로 전환 예정
- **발표자 노트**
  - 지금 화면은 시뮬레이터 결과입니다. 실제 기기에서 브롤스타즈를 켠 채 버튼을 눌러 보는 확인이 남아 있습니다.
  - 실제 내 브롤러와 열린 맵을 보려면 다음 순서로 설정해야 합니다.
    1. Supercell 개발자 사이트(developer.brawlstars.com)에서 키를 발급합니다. 서버 IP를 등록해야 합니다.
    2. 서버를 배포합니다.
    3. 앱 설정(`PUSH_RELAY_URL`)에 서버 주소를 넣습니다.
  - 서버가 없어도 맵 직접 선택과 ◀ ▶(랭크 맵 순서)는 동작합니다.
  - 공식 API에 실시간 정보가 없다는 한계는 앱이 아니라 데이터 제공 쪽의 한계입니다.
